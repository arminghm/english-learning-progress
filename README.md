# English Interview Lab

برنامهٔ تمرین مکالمهٔ انگلیسی و مصاحبهٔ مهندسی نرم‌افزار، با داشبوردی که فقط بر اساس تمرین‌های ثبت‌شده قوت و ضعف را نشان می‌دهد.

## شروع سریع

1. [داشبورد](docs/index.html) را ببینید. پس از فعال‌سازی GitHub Pages، همین فایل به صورت وب نمایش داده می‌شود.
2. [برنامهٔ ۸ هفته‌ای](PLAN.md) را دنبال کنید: روزی ۶۰ دقیقه، ۵ روز تمرین اصلی + یک مصاحبهٔ آزمایشی + یک روز مرور.
3. [سنجش اولیه](BASELINE.md) را در مکالمه با مربی انجام دهید. امتیازهای اولیه تا پاسخ واقعی شما ثبت نمی‌شوند.
4. پس از هر جلسهٔ معنادار، یک فایل جلسه بسازید و آن را به داده‌ها اضافه کنید:

   ```sh
   cp data/session.example.json /tmp/my-session.json
   # فایل موقت را با نتیجهٔ واقعی جلسه ویرایش کنید
   node scripts/add-session.mjs /tmp/my-session.json
   ```

5. با هر commit در شاخهٔ `main`، داشبورد GitHub Pages از داده‌های مخزن به‌روز می‌شود.

## شیوهٔ سنجش

داشبورد مهارت‌ها را از امتیازهای **سنجش مستقل و بدون راهنمایی** محاسبه می‌کند. دو سنجش مستقل لازم است تا یک مهارت «قوت» یا «نیازمند تمرین» نام بگیرد. تمرین روزمره در مجموع زمان و تاریخچه دیده می‌شود، اما به تنهایی رتبهٔ مهارت را تغییر نمی‌دهد. مقیاس ۱ تا ۵ و معیارهای هر مهارت در [راهنمای سنجش](RUBRIC.md) آمده است.

> این مخزن می‌تواند عمومی باشد. نام شرکت، متن محرمانهٔ مصاحبه، صدای شخصی یا اطلاعات تماس را در آن ثبت نکنید.

## روال همکاری با مربی

در ابتدای هر جلسه در همین گفتگو بنویسید: «تمرین امروز را شروع کنیم». مربی یک موقعیت مصاحبه را به انگلیسی شروع می‌کند، پاسخ شما را می‌شنود/می‌خواند، سپس بازخورد کوتاه فارسی، نسخهٔ بهتر پاسخ، سه عبارت کاربردی و یک تمرین تکرار می‌دهد. بعد از یک سنجش مستقل، نتیجه را با شناسهٔ شاهد در مخزن ثبت کنید.

## ساختار

- `PLAN.md`: برنامه و معیار عبور از مراحل
- `BASELINE.md`: سنجش آغازین
- `RUBRIC.md`: معیار امتیازدهی
- `data/progress.json`: جلسات و امتیازها؛ منبع دادهٔ داشبورد
- `docs/`: داشبورد ایستا برای GitHub Pages
- `scripts/add-session.mjs`: اعتبارسنجی و افزودن جلسه

## انتشار در GitHub Pages

در تنظیمات مخزن، **Settings → Pages → Build and deployment → Source: GitHub Actions** را انتخاب کنید. گردش‌کار موجود در `.github/workflows/pages.yml` سپس در هر تغییر `main` فایل‌های `docs/` و داده‌ها را منتشر می‌کند. اگر Pages در حساب شما فعال نباشد، فایل‌ها همچنان در خود مخزن قابل مشاهده و ویرایش‌اند.
